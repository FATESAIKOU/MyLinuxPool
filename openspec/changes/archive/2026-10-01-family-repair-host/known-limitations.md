# 已知限制總表（家人維修承載機，issue #6）

> 2026-09-30 整理；臨時跳板改版後更新（第一版 `NODE_*` 登錄、每台一個包的
> 限制已隨改版消失）。這裡列的都是**刻意不做**或**沒驗到**的項目，每條都寫了它會怎麼表現、為什麼接受。
> 「使用者決定」＝本人知情後的選擇；「未驗」＝目前沒有證據，只能靠推論。

## 安全

| 項目 | 表現 | 為什麼接受 |
|---|---|---|
| 隧道金鑰沒有收窄 | 家人電腦裡的隧道私鑰一旦外洩，對方能在 Gateway 上以 `sshproxy` 拿到 shell（不是 root），也能監聽任意 port。改版後全家共用同一把，代價見下一條。池裡每一把隧道金鑰都是這樣 | 使用者決定。另外：`restrict`＋`permitlisten` 擋不住遠端執行指令，而 `pool-tunnel` 的健康檢查需要遠端執行，所以日後要收窄不能只靠 permitlisten |
| 共用隧道私鑰外洩影響全家 | 任何一位家人的電腦外洩，對方能冒充任何一位家人、佔住整段 port；且止血＝換金鑰＋全家重裝，沒有只封一台的辦法 | 使用者決定（一把鑰匙全家用是設計 D9；家人不多，換得起） |
| 名字沒有認證，任何拿到包的人可冒名 | 名字是家人自己打的；兩台取同名也能連上。`mlp ssh` 連上後仍要使用者的金鑰才能登入，但使用者可能登入到冒名的那台——動手前先跟家人對狀態 | 認證名字需要每台一份 credential，正是改版拿掉的東西；design 已知風險（改版的新風險第 2 條） |
| 每次開機重新信任 Gateway 主機金鑰 | VM 開機時清掉 known_hosts，等於每次都 accept-new；第一次連線時若被中間人冒充，對方最多拿到一條指向 VM sshd 的轉發，登入仍需要使用者的金鑰 | 換來的是 Gateway rotate 或 IP 換手後不會被鎖在外面；「先釘、不符退回」可選，未做 |
| 登入授權是打包當下的快照 | 新增或撤掉 client 公鑰，已發出去的包不會跟著變；要重打一份包交給家人 | 使用者決定：換來 VM 不需要任何 GitHub 權杖 |
| 開機資料與安裝包裡有隧道私鑰 | 包怎麼交給家人由使用者負責；Windows 上的資料夾已鎖成只有該使用者與 SYSTEM 能讀 | 家人那端不能做任何設定，私鑰只能從 Mac 帶過去（design D4） |
| repo 是公開的 | Actions log、歷史 commit 任何人都看得到。歷史裡有加密過的舊私鑰；稽核確認它們對應的金鑰已經沒有任何地方接受（`OUT-public-key-audit.md`），但 fh-l 的 Linux 側授權清單因為當時開在 Windows 而沒查到 | 使用者為了讓 Actions 免費而改成公開 |

## 功能

| 項目 | 表現 | 為什麼接受 |
|---|---|---|
| 撤掉某一位＝全家重裝 | 沒有「只撤一台」的開關；換共用金鑰＋每一家換新包重開（design 裁示） | 家人不多，換得起 |
| 名牌是快取，`mlp` 以 listener 為準 | 非常態關機（斷電）可能留下名牌殘留；有檔沒 listener 不顯示，有 listener 沒檔顯示為無名 | 名牌只管顯示，授權只認 `authorized_keys`；殘留不影響安全，家人重開一次即消失 |
| 名牌內容不可信 | 拿到共用金鑰的人能改寫任何名牌，讓 `mlp ls` 顯示錯的名字、讓 `mlp ssh <名字>` 連到另一台在線的跳板，或讓某個名字消失。`mlp` 只把名牌當標籤：port 一律取自 Gateway 上實際的 listener（只認 `127.0.0.1`），名牌內容整行不合格式就顯示 `?`、不能以名字連；控制字元、換行、偽造的 listener 都進不了輸出（`OUT-review-mlp-nameplate-fix.md`）。要確認連對台，登入後看 hostname，或用 `mlp ssh <port>` | 名字本來就沒有認證（上一條）；徹底的遠端分幀（base64）可做但不增加安全性 |
| `pool-status` 的 `2000–2999` 摘要行會列出跳板 port | 只有數字、沒有名字，不報警 | 沿舊行為（design D11 明說不改）；名字只在 `mlp` 的 repair 區 |
| Gateway rotate 後家人要重新輸入 IP | 啟動器在連不上約 5 分鐘後顯示「連不上，請向使用者索取新的 IP」 | 沒有不隨 rotate 改變的名稱（DDNS 已廢） |
| 關閉 VM 的路徑 | 按 X、Alt+F4、PowerShell 結束都會送 ACPI 關機；用工作管理員強制結束或斷電則不會，下次啟動會沿用還在跑的 VM | 系統層級的強制終止攔不到 |
| 重試節奏依賴 fail2ban 的預設值 | 被拒後等 310 秒，任何 10 分鐘內最多 2 次；Gateway 若日後改成更嚴的 fail2ban 設定（例如 recidive、maxretry 3），要重新檢查 | 目前的設定就是預設值 |
| 家人區網若是 `10.0.2.0/24` | 會跟 VirtualBox NAT 的預設網段撞，連不到家人的路由器；要改 `--natnet1` | 常見家用網段不是這個 |
| 家人電腦開著 Hyper-V | VirtualBox 會退到比較慢的模式 | 功能不受影響 |
| VM 被外部關掉時啟動器不會跟著結束 | 從 VirtualBox 或指令關掉 VM，「維修連線」視窗仍開著並佔住 18080，要手動關窗；同一台電腦同時只能開一個啟動器 | 家人只會用關窗這條路；2026-09-30 真機觀察到 |
| provider 的 pool-sync 每 30 分鐘無條件觸發 refresh | issue #7；merge 前會把只在分支上的共用鑰洗掉，merge 後無影響（master 認得 `REPAIR_TUNNEL_PUBKEY`） | 另案處理 |
| 啟動器用固定的本機 port（18080） | 被佔用時啟動器拒絕並顯示中文訊息，不會開機 | 衝突的機率低；訊息看得懂 |
| 映像從 Ubuntu 官方下載 | 首次安裝要能上網；SHA256 在打包時寫進設定，官方日後換版會對不上而拒絕，要重新打包 | 不把 600MB 放進包裡 |
| VirtualBox 版本 | 只實際驗過 7.2.20（build 175154） | — |
